# Security Policy

This document covers three things: reporting a vulnerability, reporting abuse of this software, and removing the application from a device where it was installed without consent.

---

## Supported versions

| Version | Supported |
|---|---|
| 1.0.x | Yes |
| < 1.0 | No |

Security fixes are released against the latest tagged version. There are no long-term-support branches.

---

## Reporting a vulnerability

Report security issues privately. **Do not open a public GitHub issue for a vulnerability.**

**Email:** [norypt@proton.me](mailto:norypt@proton.me)

Please include as much of the following as you have:

- The affected version and the device model and Android build.
- Which privilege tier the device is in — Device Admin or Device Owner.
- Reproduction steps, or a proof of concept.
- The impact you believe the issue has.

**What to expect.** We acknowledge reports within 5 business days and aim to give an initial assessment within 15 business days. If a report is accepted, we will agree a disclosure timeline with you and credit you in the release notes unless you prefer otherwise. If it is declined, we will explain why.

We do not operate a paid bug bounty.

### Issues of particular interest

- Any path that causes a wipe without the owner's configured trigger firing.
- Any path that bypasses the dry-run default on a fresh install.
- Any bypass of the App PIN gate or the launch-time signature verification.
- Any way for an unsigned or differently-signed third-party application to fire the `A5` or `A7` external triggers.
- Any data leaving the device. The application declares no `INTERNET` permission, so any such finding is severe by definition.

### Out of scope

- Attacks requiring root access or an unlocked bootloader. These are documented as out of scope in the project threat model.
- Physical attacks on hardware, such as chip-off or JTAG.
- The absence of PIN recovery. This is a deliberate design decision, documented in the README.
- Reports generated by automated scanners with no demonstrated impact.

## Reporting abuse of this software

This project publishes a tool that can erase a device. That capability can be misused. We take reports of misuse seriously.

**Contact:** [norypt@proton.me](mailto:norypt@proton.me), with `ABUSE` in the subject line.

Please report it if you believe this software is being used to:

- Operate on a device without the knowledge and consent of the person who owns or uses it.
- Deny someone access to their own device or data, including for extortion.
- Destroy data in order to obstruct a legal process.
- Do anything else prohibited by the *Intended use and restrictions* section of the [README](README.md).

Include whatever you can establish about the situation. If you are a platform, registrar, or law-enforcement body making an inquiry, say so and we will respond through the appropriate channel.

We will not assist in configuring or deploying this software on a device the requester does not own or is not authorised to administer, and we do not provide support for doing so.

## If this application is on your device and you did not install it

Norypt Protect **cannot read your messages, record audio or video, capture your screen, or determine your location, and it has no network permission, so it cannot send anything anywhere.** It is not spyware. What it can do is lock or erase the device.

It is still not acceptable for someone to have installed it on your phone without telling you. Here is how to check for it and remove it.

### 1. Confirm whether it is installed

The application can be hidden from the app drawer, but it is always listed in Settings.

- **Settings → Apps → See all apps**, then look for **Norypt Protect**. Enable *Show system apps* if your device offers that filter.
- Or, from a computer with Android platform-tools installed:

```bash
adb shell pm list packages | grep norypt
```

### 2. Check which privilege tier it holds

- **Settings → Security → Device admin apps** shows whether it is an active Device Admin.
- From a computer:

```bash
adb shell dpm list-owners
```

If that command returns a Norypt Protect component, the application is **Device Owner**. That tier can block its own uninstallation.

### 3. Remove it

**If it is only a Device Admin:** deactivate it in Settings → Security → Device admin apps, then uninstall it normally in Settings → Apps.

**If it is Device Owner:** it cannot be uninstalled from Settings, by design. A factory reset removes it. **A factory reset erases the phone**, so back up anything you need first, ideally to a computer or an account you control exclusively.

### 4. Before you reset, consider preserving evidence

If someone installed this on your device without your consent, that may be relevant to a legal or safety process. A factory reset destroys that record. Consider photographing the Settings screens that show the application and its Device Owner status before you reset, and consider seeking advice first.

If you are in danger, contact your local emergency services or a domestic-violence support organisation. The [Coalition Against Stalkerware](https://stopstalkerware.org/) publishes resources and can direct you to help in your country.

**Emergency calling is not affected by this application.** It includes an optional setting that turns off Android's five-press Emergency SOS *gesture*, but dialling emergency services from the dialer and the *Emergency* button on the lock screen are separate systems that it does not touch.

## Verifying an official release

Only install builds signed with the Norypt release certificate.

```bash
sha256sum norypt-protect-<version>.apk
apksigner verify --print-certs norypt-protect-<version>.apk
```

The certificate SHA-256 must be:

```
13:50:25:10:A5:B5:0D:59:BF:78:23:CB:E5:96:B8:8C:7B:4C:B5:4B:41:BC:21:7A:AC:7C:25:19:17:53:6E:95
```

The fingerprint is published in the README, on [norypt.com/protect](https://norypt.com/protect), and in each release's notes. If those sources disagree, do not install, and report it to [norypt@proton.me](mailto:norypt@proton.me).

Release builds also verify their own signing certificate at launch and refuse to run if it does not match the pinned value, so a repackaged APK will not start.
